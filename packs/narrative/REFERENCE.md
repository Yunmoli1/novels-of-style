# narrative 类型包：叙事结构领域知识

> 分工：本文件管**结构上写什么**（章节骨架、钩子、节奏），风格包管**句子怎么写**
> （节奏、词汇、对话质感）。style-apply 在写叙事类作品时加载本文件。

## 一、网络小说长篇结构

### 金三章（开篇生存法则）
- 第 1 章：冲突开场（不要从早晨起床写起），首 500 字内出现主角 + 张力事件；
  章尾留第一个钩子
- 第 2–3 章：立住主角欲望与障碍，给出第一个"小满足"，让读者确认追读收益

### 单章结构（2000–4000 字/章）
1. 承接（1–2 段接上一章钩子，不复述）
2. 推进（1–2 个场景，每场景有信息增量或关系变化）
3. 收尾钩子（四选一）：危机迫近 / 悬念揭示一半 / 反转 / 新期待

### 爽点节奏
- 压抑—释放循环：小爽点每 2–3 章一次，卷末给大爽点
- 连续压抑不超过 3 章，否则读者流失；释放要给足篇幅，不一笔带过

### 人设与伏笔（bible 维护约定）
- `characters.md`：每个主要人物含【欲望 / 恐惧 / 说话特征 / 行为红线】四要素
- `foreshadowing.md`：每条伏笔记【埋设章节 / 预计回收 / 状态(未收|已收)】，
  埋设当天登记；consistency-check 会逐条对账
- `timeline.json`：事件带 order 与章节引用，供脚本校验

## 二、文艺叙事

- **意象系统**：选定 2–3 个核心意象（物件/天气/颜色），全篇复现并承担情感
- **潜台词对话**：重要对话不把意思说破，用动作与物打断
- **抒情节制**：情绪一律外化为景与动作，不直接命名情绪
- **场景转换**：空行或一句景语切换，不写"与此同时"式的说明文转场

## 三、与风格包协作 checklist

| 时机 | 动作 |
|---|---|
| 写前 | style-apply 锚定协议：钉扎包 + bible 相关条目 + 上一章结尾 |
| 写中 | 人物对话按 characters.md 声线区分；结构按本文件 |
| 写后 | fp_check（量化）+ style-critique（质感）+ consistency-check（增量体检） |
| 卷末 | style-calibrate 盲测（制度化）+ consistency-check 全量漂移网 |

## 红线

- 结构需要破例时（如整章抒情缓冲），在 reviews/ 留一句理由，防漂移
- 设定冲突时以 bible 为准；bible 错了先改 bible（走 consistency-check 报告流程），
  不允许稿子悄悄偏离设定
