# style-apply：按风格包写作

## 上下文加载协议（按顺序，上下文紧张时从上往下裁）

1. `style/pinned-pack.md`（钉扎版本）；若上下文预算小，只取其中「精华卡」+「禁用清单」
2. 正常预算：完整档案（profile.md）+ 思想档案（thought.md，若有）+
   词汇与句式（lexicon.md）+ 能力边界（limits.md）
3. 从范例（exemplars.md）挑 3–5 条与本次场景最近的，作为 few-shot 对照；
   包内含 registers.md（调子分区）时优先从**本章声明调子的分区**里挑
   （编号见 registers.md「示范段路由」，条目批注下的「调子：」行可核对）；
   未声明调子、或该分区无示范段 → 全部范例照常参与挑选
4. `bible/` 中与本章相关条目（characters.md 的人物声线、world.md 的设定、
   foreshadowing.md 中本章涉及项）
5. **章节锚定**：上一章结尾原文（至少最后 3 段）；跨章续写必读，防止风格与情节断层

叙事类作品同时读取 `packs/narrative/REFERENCE.md` 的结构指导
（单章结构、钩子、爽点节奏——REFERENCE 管"结构写什么"，风格包管"句子怎么写"）。

**加载纪律（硬性）**：上述文件放在**同一轮并行工具调用**中一次读齐，
禁止逐个串行加载（每次调用都重发会话历史，串行 = 数倍开销）。
写短篇段落或上下文预算紧张时，降到最小集：card + 禁用清单 + 本章相关 bible 条目。

## MCP 自动化（透明编排：用户只说"继续写"）

宿主已连接 stylepack MCP 时，用 MCP 替代对应的手工步骤，用户无需看到这些步骤：

- 开工：story.sync（幂等）→ story.recap + story.character（本章出场实体）
  替代上面第 4、5 条的直读 bible / 上章结尾；缺口用 story.search 按需补片段
- 写完：story.propose_delta 登记变更与摘要（风险分级不变：低风险自动合并留痕，
  中 / 高风险待用户确认后 story.merge_delta force）
- **验收分两步**：fp.check（MCP）做过程内快速判定；章节收尾仍跑本地
  `fp_check.py --report --save-metrics` 留档——MCP 版 fp.check 暂不带留档与
  `--baseline` 对比，revise 模式依赖留档文件
- 风格包本体（card / profile / lexicon）仍从钉扎文件装载：MCP 替代的是动态
  故事状态、检索、登记、验收，不替代静态风格资料
- 无 MCP 时按原协议读文件；两条路径不混用（单一首选路径原则）
- 输出语域：面向用户一律用意图语言（"我先把设定和前情过了一遍"）；
  工具名只出现在诊断修复语境，或用户明确要求技术细节时

## 写前共创（先干后写：两级确认后才生成正文）

正文生成是全流程最贵的动作，先花小钱确认方向，避免整章废稿：

1. **第一级·立意确认（包内有 thought.md 时）**：依 thought.md 提 2–3 个
   立意方向，每个 = 题材角度 + 拟用立意动作（引条目）+ 价值姿态落点，
   呈用户选定
2. **第二级·拍子表确认**：选定立意后产出**本章拍子表**：开场承接 /
   场景 1 / 场景 2 / 结尾钩子，每拍一行（写什么、出现谁、给读者什么）；
   包内有 registers.md 时附一行**调子声明**（从分区定义里选，或写
   "不指定"），呈用户一并确认——调子决定示范段路由与读者感知的调门，
   不改变验收判定
3. 用户调整后锁定拍子；拍子涉及的新设定 / 新伏笔落入 `bible/pending/`
   隔离区（见下方「设定落库仪式」），**不直接写正式 bible**
4. 拍子确认后才进入正文生成，生成严格按拍子推进，不新增情节线
5. 写短篇段落、或用户明确说"直接写"时两级都跳过

## 设定落库仪式（隔离区 + 风险分级，防污染权威源）

正式 bible 是全项目的准绳，任何来自拍子 / 正文的新设定必须经隔离区合并：

1. 新设定写入 `bible/pending/`（characters-pending.md / world-pending.md /
   foreshadowing-pending.json / timeline-pending.json），格式与正式文件一致，
   逐条注明来源章节
2. **脚本校验（零成本，条条过）**：`names_check` 查重名 / 别名冲突；
   `timeline_check` 查事件顺序矛盾
3. **风险分级（确认成本随风险增长，不随数量增长）**：
   - **高风险 → 阻断确认**：核心人物（names.json 中 `tier: "core"`）的属性或
     关系变动、关键剧情道具、一切伏笔
   - **中风险 → 批量确认**：时间线事件、次要人物（`tier: "minor"`）的重要变动
   - **低风险 → 自动合并 + 留痕**：全新路人、无关紧要的地名等不影响既有设定的新实体；
     合并即记入 `bible/pending/merged.log`（日期、来源章节、内容摘要），
     章节收尾时给用户一条批量摘要，随时可撤销（工作区已 git init，回退提交即可）
4. 分级依据：names.json 每个人名带 `tier` 字段（core / minor，建档时标定）；
   分不清的按高一档处理
5. 语义级矛盾由 consistency-check 的增量检查兜底；
   用户明确指令（"把这个设定直接写进 bible"）可跳过隔离区直达正式文件

## 写作纪律

- limits.md 标注【难模仿】的维度，不要硬仿，宁可平实
- 禁用清单（lexicon.md）中的词与句式绝对不出现
- 人物对话必须能区分声线：以 characters.md 的口头禅 / 句长 / 语气为准

## 写完必验收（不可跳过）

```bash
python scripts/fp_check.py <包目录> <本章输出文件> --report <项目>/reviews/fp-<章号>.md \
  --save-metrics <项目>/reviews/fp-<章号>.metrics.json
```

`--save-metrics` 留档本章实测指标，供 revise 时 `--baseline` 做前后对比。
分层包（fingerprint 含 genres）自动按文本文体选层验收，无需指定。
在意思想层时加 `--thought`：输出 motif 密度对照（advisory，不进判定）。

- 通过 → 交付，附报告路径
- 不达标 → 向用户报告偏差最大的指标，针对性修订后复检（改句子节奏，不是改数字）
- 禁止为了凑指标在句尾机械添删标点；指标是体检表，不是写作目标

## 局部重写（revise 模式：改段落，不重写全章）

输入为批改报告 / 一致性报告的 P0/P1 定位清单时，走本模式：

1. 逐条读取报告中的定位（章节 + 段落 + 问题 + 建议），按严重度排序
2. **只重写被点名的段落**，未被点名的段落一字不动
3. 每处修改同时满足：修掉问题本身、与前后文接缝自然、不引入禁用清单项
4. 全部改完复跑 fp_check，带 `--baseline <上次 .metrics.json>` 逐指标对比：
   基线在容差内而本次超容差的指标视为**回归**，回滚该处重做；
   同时 `--save-metrics` 更新留档
5. 输出修改清单（改了哪几段、为什么），不重出全文

## 输出

正文写入 `manuscript/NNN-标题.md`（与既有章节编号连续），报告中给出指纹结论。

## 交付声明制（思想层，v0.3）

包内有 thought.md 时，交付必须声明本篇**使用了哪些立意动作与意象**
（引用 thought.md 条目），用户可对照检查——这是"包内容真的装了没有"
的验收对应物；未使用 thought.md 的包不适用此条。

### 思想层收尾检查（硬性，盲测 R3 教训）

包内有 thought.md 时，交付前**重读最后一段**：是否在给人物立抒情碑、
给读者安慰、点题升华？thought.md「禁区」明令不给的一律重写收尾再交付。
依据：思想盲测 R3——带包段以"霜地上……白得比别处更白些"式意象收尾被
判官点名（违反"结尾不给安慰"），为当轮唯一失利主因
（evals/calibration.json `thought_blind_v030`）。

### 借句初筛（可选门，v0.4.2）

包内 exemplars.md 存在时，交付前可跑
`python scripts/borrow_check.py <稿> --pack <包目录>`：命中 ≥12 字逐字
重叠即"整句搬运"信号（盲测两败同因），命中的句子**改写后交付**。
初筛不是终判——化用/骨架雷同不在其射程，仍靠盲测与人工判读兜底。
exit 0=未命中 1=命中 2=用法错误。

## 收尾自检（防静默跳步，逐项明示）

交付前向用户明示以下各项的执行结果（做了 / 跳过及原因）：

```
锚定协议 ✓/✗ ｜ 立意共创 ✓/✗/不适用 ｜ 拍子确认 ✓/✗ ｜ 调子路由 ✓/✗/不适用 ｜ 落库分级 ✓/✗ ｜ fp_check+留档 ✓/✗ ｜ 借句初筛 ✓/✗ ｜ 记账 ✓/✗ ｜ 交付声明 ✓/✗/不适用 ｜ 收尾检查 ✓/✗/不适用
```
