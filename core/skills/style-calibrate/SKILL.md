# style-calibrate：A/B 盲测

档案质量不靠自我感觉，靠用户盲测胜率。

## 流程

1. **出题**：与用户商定 3–5 个与原作无关的中性提示（如"写一段冬天的集市"），
   存入 `<项目>/style/calibration-prompts.md`。**思想盲测（v0.3，包含
   thought.md 时）**：改用"同题材两问"逼成立意差异——同一题材请写两种
   不同立意；判读问题从"哪段更像"细化为"哪篇更像**这个作者在思考**"；
   出题模板内置如下，用户保留否决权
2. **生成**：每个提示生成两段——A=带包（style-apply 完整协议），B=不带包
   （同模型、同提示、明确要求"用你自己的默认文风"）
3. **盲选**：打乱两段的呈现顺序与标签，逐对请用户选"哪个更像目标作者"，
   允许选"都不像"；**绝不透露哪段带了包**
4. **计分**：写入 `<项目>/style/calibration.json`：

```json
{"rounds": [{"date": "2026-09-28", "prompt": "冬天的集市",
  "pack_version": "0.1.0", "winner": "A|B|none", "notes": ""}]}
```

5. **复盘**：胜率 = 选带包段次数 / 有效轮次

## 节奏（制度化，不是可选项）

- **每卷收尾 / 每约 30 章必跑一轮**——指纹验收只能证明"统计上达标"，
  只有盲测能证明"读者觉得像"；两者缺一即验收不完整
- **胜率较上轮下滑 ≥ 20 个百分点 → 触发档案复审**：复盘 notes 定位薄弱维度，
  转 style-feedback 提修订提案；连续两轮下滑暂停该包对外使用

## 判读

- **≥ 70%**：包成熟，可依赖
- **50–70%**：可用但需迭代：复盘用户"notes"，把选 B 的理由归因到维度
  （节奏 / 词汇 / 对话 / 结构），转 style-feedback 提修订提案
- **< 50%**：包失效或不适配该文体：检查是否钉错包 / 用错类型，
  必要时回到 style-analyze 重蒸馏

## 纪律

- 带包段必须走完整 style-apply 协议（含验收），否则测的不是包而是运气
- 每轮记录 pack_version；升版后历史胜率不合并
- 结果如实呈现，不为好看调整口径
