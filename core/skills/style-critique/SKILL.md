# style-critique：审计者批改

## 审计者分离原则

本技能必须在**未参与写作**的上下文运行：宿主支持子代理/新会话时，以独立会话执行；
不支持时，提醒用户开新对话调用本技能。审计者不复用生成者的任何辩护性上下文。

## 输入

1. 项目钉扎的风格包（profile + exemplars + lexicon + limits）
2. 待批改文本（单章或若干章）

## 成本纪律（硬性）

- **开跑预告 + 落账**：批改前向用户预告读取量（包文件 + 章节字数）与子代理数量；
  完成后记一笔账：
  `python scripts/cost.py log --skill style-critique --chars <字数> --project <项目>`
- 风格包文件与待批改文本放在**同一轮并行工具调用**中一次读齐，禁止串行逐个读
- **多章批量批改**：每章派一个独立子代理（各读该章 + 摘要版档案，互不携带
  对方上下文），主会话只汇总各章报告——不要在同一个会话里累积读完所有章节
- 子代理用的**摘要版档案** = card + 禁用清单 + fingerprint 阈值表（合计 ≤ 1000 字），
  逐条引证仍由子代理按需定点读 exemplars.md 对应条目

## 批改维度（逐维过，不合并）

| 维度 | 对照依据 | 找什么 |
|---|---|---|
| 句子节奏 | profile「句式与节奏」+ fingerprint | 长短句分布偏离、单调连排 |
| 词汇指纹 | lexicon.md | 标志词缺失、禁用词出现、词域越界（现代词入旧语境等） |
| 对话风格 | profile「对话风格」+ characters.md | 人物声线混淆、对话信息过载、说破潜台词 |
| 场景与结构 | profile「场景与结构」 | 转场生硬、开头承接断裂、结尾无钩子 |
| 情感与氛围 | profile「情感与氛围」+ limits | 情绪直说而非外化、抒情过度 |

## 意见格式（每条）

- **[维度] 标题**（严重度 P0 致命 / P1 重要 / P2 建议 / P3 吹毛求疵）
- 定位：引用原文 ≤ 40 字，注明段落
- 证据：引用风格包依据（某条范例的批注 / 某项指纹指标的偏差 / 禁用清单第 N 条）
- 建议：一句话可执行的改法；**不整段重写**

## 输出

写入 `<项目>/reviews/critique-<日期>-<章号>.md`，开头给总体结论
（最像的 3 点 / 最不像的 3 点），结尾按严重度排序意见清单。
明确告知：风格目标以钉扎的包版本为准，包本身的问题请走 style-feedback 修订档案。
