# writing：写作前门

本技能只做路由，不写正文。按下方路由表**从上往下**取第一个命中的信号分流；
路由落定后**读取目标技能的 SKILL.md**（与本技能同级：`../<技能名>/SKILL.md`）
并严格按其执行——不读文件、凭记忆复刻流程视为未路由。

**仓库根定位（读包文件前必做一次）**：仓库根 = 含 `stylepacks/`、`scripts/`、
`core/skills/` 特征目录的那一层。从 cwd 找起：cwd 有这些特征即仓库根；没有则
在 cwd 的子目录里找一层；再没有 → 放弃文件路径，改用 MCP（自带定位，见下）。
对话 cwd 与仓库根不同层是常态，不要拿 cwd 当仓库根。

| 用户信号 | 路由 |
|---|---|
| 提到自己的章节 / 人物 / 大纲 / 伏笔，或 cwd、用户路径存在 `manuscript/` 或 `bible/` | style-apply（项目全流程） |
| 口语锚点（随便写写 / 来一段 / 朋友圈 / 段子 / 文案 / 仿一下）且无项目信号 | 轻模式（见下） |
| "分析 / 建档 / 蒸馏某作者文风" | style-analyze |
| "拆解 / 精读 / 人物关系图 / 结构分析" | close-read |
| "检查 / 批改 / 这段不像改改" | style-check（量化）或 style-critique（质感） |
| "测测档案准不准 / 盲测" | style-calibrate |

## 路由纪律

- **条件默认，双向成立**：锚点命中但用户提及自己的章节人物 → 项目模式
  （"第三章要写到主角发朋友圈"仍走项目模式）；项目目录内用户说
  "不走流程 / 直接写" → 尊重，走轻模式
- **让位**：用户点名了其他技能则不经本技能；一旦进入子技能，按其流程走到底，
  不回前门
- **消歧**："这段不像，改改" → 批改路线；"这段不像，记下来 / 记住" →
  style-feedback（只登记不改稿）
- 本技能只拦创作产出、改进与拆解；建工作区（style-setup）、语料入库
  （corpus-ingest）、包管理（stylepack）不是创作请求，直接走对应技能

## 轻模式（一次性小写作，≤3 个工具调用）

1. **气质匹配优先于默认包**：请求文体与现有包气质明显不符（"朋友圈文案 / 段子"
   vs 鲁迅）→ 不套包直接写，一句话说明即可；用户点名作者（"仿一下鲁迅"）→ 套
   对应包；气质接近且未点名 → 供用户选包
2. **取包路径（单一首选：MCP）**：宿主已连 stylepack MCP → 用 `stylepack.info`
   列可用包（不传 name 即清单；name 可传中文名"鲁迅"或目录名"luxun"），MCP
   自带定位，与 cwd 无关，**优先于任何文件浏览**。无 MCP → 按"仓库根定位"找
   `stylepacks/` 后列出
3. 套包时只读 `card.md` + 禁用清单（≤1KB），按需取 3 条 exemplars 做 few-shot；
   请求带调子词（"冷峻一点 / 温情一点"）且包内有 registers.md（单文件包含
   「调子分区」节）→ 只取该调子分区路由的示范段，无对应示范段则全部 exemplars
   照常取。用户直接给或指向单文件包（`*.stylepack.md`）→ 读它即可，不找目录
4. 直接写 → 交付；fp_check 仅在用户表达"在意像不像"时跑
5. 跳过拍子确认、工作区、bible、落库、记账（无项目可记）

## 失败行为规范（防编造、防静默降级）

- **探测失败不等于事实断言**：没亲眼列出目录内容之前，禁止对用户说
  "目录为空 / 没有 XX 包"；只能陈述"按 X 路径没找到"，并换下一条路径再试
  （MCP → 仓库根定位 → 单文件包 → 问用户包在哪）
- **点名作者的请求，套包失败必须上报选项**：(a) 修好路径后套包写（推荐，产出
  可验收）；(b) 不套包、凭先验印象直接写（无指纹无验收，不算 StylePack 产出）。
  禁止不声明就滑向 (b)——用户点名作者要的是包内的作者，不是模型印象里的作者
- 两条路径都走不通时如实告知 + 给选项，宁可多问一句，不可编一个理由继续

## 输出语域（管沟通不管不变量）

面向用户一律用意图语言（"我先把设定和前情过了一遍"）；工具名（story.sync 等）
只出现在诊断修复语境，或用户明确要求技术细节时。

## 维护
