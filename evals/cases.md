# 评估用例（金标准）

> 用法：这些用例由 agent / 人工执行，结论记入 `reviews/` 或 PR 描述。
> CI 只跑机器可判定的部分（unittest + validate_pack）；风格类用例在发布前与
> 改动风格包内容时必须跑。

## Case A：鲁迅包模仿（narrative）

- **提示**：使用 stylepacks/luxun，写 200–300 字：第一人称，回乡在村口遇见儿时同伴，如今境遇悬殊。
- **期望特征清单**（命中 ≥ 5 视为通过）：
  1. 短句为主，偶以"然而/但/却"转折
  2. 至少一处矛盾修饰或模糊断语（"大约…的确…"类）
  3. 环境描写 ≤ 2 句且带象征义（不堆砌）
  4. 对话 ≤ 3 个来回，人物话语有身份感
  5. 结尾留余味（断语 / 反问 / 景语收束），不总结主题
  6. 无网络流行语、无欧化长定语、无滥用"的"字连串
- **机器验收**：`fp_check.py stylepacks/luxun <输出>` 通过

## Case B：朱自清包模仿（narrative）

- **提示**：使用 stylepacks/zhuziqing，写 200–300 字：夜色中的站台送别。
- **期望特征清单**（命中 ≥ 5 视为通过）：
  1. 叠词出现 ≥ 2 处（如"渐渐""微微"）
  2. 至少一个比喻，取材日常且清新（不当拉硬拽的博喻）
  3. 长句铺陈与短句收束交替
  4. 感官细节 ≥ 2 种（视觉/听觉/嗅觉…）
  5. 情感不直说，以景与动作外化
  6. 对话可有可无；出现则平实口语，不长篇大论
- **机器验收**：`fp_check.py stylepacks/zhuziqing <输出>` 通过

## Case C：指纹验收工具自证

- **操作**：对一段明显口语网文文本运行
  `fp_check.py stylepacks/luxun <文本>`，预期**不通过**（exit 1）且报告能指出偏差最大项。
- **判定**：工具能把"不像"翻译成可读的量化偏差。

## Case D：一致性检查召回

- **操作**：取 3 万字左右的样稿（或本项目 manuscript），人工植入 5 处错误：
  2 处人名错写、1 处时间线矛盾、1 处人物认知越界（说了不该知道的）、1 处伏笔丢失；
  运行 consistency-check 技能。
- **判定**：召回 ≥ 4/5；报告能区分"改稿"与"改 bible"。

## Case E：A/B 盲测（发布门槛）

- **操作**：style-calibrate 全流程，3–5 个中性提示。
- **判定**：胜率 ≥ 50% 可发 0.1.x；≥ 70% 视为包成熟。

## Case F：分层指纹与真迹包络（v0.2.3 金标准，离线可跑）

- **数据**：downloads/corpus/（真迹 9 篇）+ 生成结果/（AI 文本）；CI 无此目录时跳过
- **三类判定分开测**：
  1. **真迹必须过本层线**（auto 选层）：秋夜/风筝→luxun essay 层 ✅；
     孔乙己/故乡/祝福→luxun narrative 层 ✅（指标+Delta 双判，线=层内留一最差篇）；
     背影→zhuziqing essay 层 ✅
  2. **错作者必须不过**：背影→luxun ❌（6/11）、匆匆→luxun ❌（7/11）、
     秋夜→zhuziqing ❌（3/12）
  3. **AI 文本落位**：文1（凭印象）与文2（用包）均不达标（各 5/11），
     Delta 参考值排序 文2(1.55) < 文1(1.67) > 真迹(≈1.03)——包有效但不达标
- **已知限制（如实入档）**：
  - luxun essay 层 n=2：留一 Delta 线不可标定，该层 Delta 仅参考；语料扩充（Case G）后重算
  - luxun narrative 层留一线 delta_max≈19（n=3 小样本方差大）：语义正确但偏松，
    收紧靠扩语料，不靠调参
  - essay 层绝对包络尚不能单独区分作者（秋夜 Delta 1.03 在 zhuziqing 线 2.11 之内，
    由指标 3/12 完成拒绝）——指标与 Delta 互补，缺一不可

## Case G：语料扩充后重算（待执行）

- **操作**：按 docs/corpus-sources.md 登记表补充《野草》全本、《朝花夕拾》、
  《阿Q正传》→ corpus-ingest → build_delta --layered 重建
- **判定**：luxun essay 层 n≥3 → 留一线可标定；Case F 第 1 类全部保持通过；
  narrative 层留一线显著收紧（delta_max 下降）

## Case H：任意作者建档与验收（通用性金标准）

> 本项目不针对特定作者。Case F 是自带包的实例，本例是**任何作者语料**都必须
> 走通的同一流程；测试 TestGenericAuthorPipeline 已机械化（合成语料 CLI 全链路）。

- **操作**（对任意作者 X 的入库语料）：
  1. `fp_extract --genre-layers` 看分层预览 → 人工核对归属是否符合直觉
  2. `build_delta <语料> --pack stylepacks/<X包> --layered` 一键产出分层阈值 +
     分层 Delta 档案 + 层内留一及格线
  3. 核对：每层 samples 正确；n<3 的层 delta_profile 为 null、留一线置空
     （如实置空，禁止手拍数充数）
  4. `fp_check stylepacks/<X包> <语料某篇真迹>` → 该篇必须过本层线
  5. 换一位作者 Y 的一篇同文体真迹 → 必须不过 X 包（或至少 Delta 参考值显著高于
     X 自己的真迹）
  6. `validate_pack` + 真迹过线全绿后才升包版本
- **判定**：2–6 全绿；任何一步失败优先怀疑语料（脏数据 / 文体混编 / 来源错乱），
  回 style-analyze 1.5 体检，其次才怀疑机制
